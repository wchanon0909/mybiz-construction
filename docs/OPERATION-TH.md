# MyBiz V1 — แนวทางใช้งานจริงและการตรวจรับระบบ

## สิ่งที่ควรทดสอบหลัง Deploy กับบัญชีจริง

- [ ] เปิดหน้าเว็บผ่าน HTTPS บนคอมพิวเตอร์และมือถือ และล็อกอิน Google Admin ได้
- [ ] Gmail ที่ไม่ได้รับอนุญาตเข้า D1/API ไม่ได้
- [ ] Invite Gmail ของ User, User Login ได้และเห็นเฉพาะโครงการที่ Admin มอบหมาย
- [ ] สร้าง Customer, Project, BOQ Lite, งวดงาน และแก้ BOQ โดยให้บันทึก Revision
- [ ] User สร้างรายจ่ายและแนบหลักฐาน R2; Admin อนุมัติ/ตีกลับได้
- [ ] ออกใบแจ้งหนี้ ยืนยันเลขเอกสารและโหลด PDF ภาษาไทยจาก R2 ได้
- [ ] บันทึกรับเงินบางส่วนและบันทึกซ้ำจนยอดค้างเป็นศูนย์ได้ แต่รับเกินไม่ได้
- [ ] สร้างและออกใบเสร็จตามรายการรับเงินจริงได้
- [ ] Reports Export CSV และ Excel เปิดไฟล์จริงได้
- [ ] เชื่อม Gmail สำหรับ Storage แล้วรูปหน้างาน/แบบก่อสร้างขึ้น Drive และดาวน์โหลดผ่าน MyBiz ได้
- [ ] ตัดการเชื่อม Google Drive แล้ว UI แจ้งข้อผิดพลาดอย่างปลอดภัย
- [ ] Export ฐานข้อมูลและมีการทดสอบ Restore ใน Environment แยก
- [ ] ตรวจว่าใบเอกสารและอัตราภาษีเหมาะกับรูปแบบกิจการโดยผู้รับผิดชอบบัญชี

## Workflow หลักที่แนะนำ

1. Settings → Company ตั้งข้อมูลกิจการ
2. Contacts → สร้างลูกค้าและ Supplier
3. Projects → สร้าง Project และเลือกผู้รับผิดชอบ → ตั้ง Contract/BOQ/Milestones
4. Finance → เพิ่ม Expense และหลักฐาน → Submit → Admin Approve → บันทึกจ่ายเงินจริง
5. Documents → สร้างเอกสารขายจากโครงการ/งวดงาน → Admin Issue → สร้าง PDF เก็บ R2
6. Documents → Invoice → บันทึกรับเงินจริงหนึ่งครั้งหรือหลายครั้ง → สร้าง Receipt
7. Reports → ตรวจยอดค้าง/งบคงเหลือและ Export Excel
8. Settings → Audit Log / Backup → ตรวจและสำรองข้อมูล

## วิธีอ่านยอดเงิน

- **งบ BOQ** = จำนวน × ราคาต่อหน่วยของแต่ละรายการ อัปเดตเมื่อมี Revision
- **ต้นทุนจริงที่อนุมัติ** = ค่าใช้จ่ายที่ผ่านการ Approve ไม่จำเป็นต้องจ่ายเงินแล้ว
- **เงินจ่ายจริง** = Payments ที่บันทึกออกแล้ว ไม่ใช่ต้นทุนทั้งหมดที่เกิดขึ้น
- **เงินรับจริง** = Payments จากใบแจ้งหนี้ที่ออกแล้ว
- **ยอดค้างรับตามบิล** = Net due ของ Invoice ลบยอดที่ชำระตาม Invoice
- **Retention** = ยอดแยกเพื่อการติดตาม ไม่รวมกับ WHT และไม่ได้กลายเป็นเงินรับโดยอัตโนมัติ
- **กำไรสุทธิทางบัญชี** = ไม่ได้คำนวณใน V1 ต้องใช้บัญชีและการปรับปรุงอื่นประกอบ

## ข้อจำกัด V1 ที่ต้องตระหนัก

- ยังไม่รองรับการแยกเงินรับครั้งเดียวไปชำระหลายใบพร้อมกัน; ปัจจุบันหนึ่ง Payment ผูกกับหนึ่งเอกสาร แต่เอกสารหนึ่งใบรับหลาย Payment ได้
- ยังไม่มีวิธีปรับยอด/ย้อนกลับ Payment ผ่าน UI หากกรอกผิดต้องให้ผู้ดูแลตรวจสอบข้อมูลและแก้ไขผ่านกระบวนการที่มี Audit เหมาะสม อย่าลบธุรกรรมใน D1 โดยพลการ
- ยังไม่มีตารางแยกติดตามการปลด Retention / คืนเงินประกันเป็นลูกหนี้รายการใหม่ จึงต้องติดตามผ่านรายงานและเอกสารประกอบ
- ตัวสร้าง PDF ภาษาไทยเป็นแบบแปลง Canvas ลง PDF เพื่อความถูกต้องด้านการแสดงผล ตัวอักษรใน PDF อาจเลือก/ค้นหาข้อความไม่ได้ และไม่ใช่ e-Tax Invoice
- R2/Drive ไม่ได้ถูกสำรองจากปุ่ม Export JSON ต้องมีแผนสำรองแยกต่างหาก
- ยังไม่มีงาน Backup อัตโนมัติไปยัง Storage แยก, ไม่มีระบบอีเมลแจ้งเตือน, ไม่มี e-Tax, ไม่มีภาษีแบบยื่นอัตโนมัติ
- Google Drive อัปโหลดได้สูงสุด 95 MB/ไฟล์ และ R2 จำกัด 20 MB/ไฟล์สำหรับการอัปโหลดตามนโยบาย V1; ข้อจำกัดนี้เป็นของแอป ไม่ใช่ของบริการ Cloudflare/Google

## การดูแลรักษา

- แยก Production / Preview bindings ก่อนทดลองเปลี่ยนฟังก์ชัน
- Backup D1 และ R2/Drive ไปยังพื้นที่อีกผู้ให้บริการตามรอบที่เหมาะกับธุรกิจ
- ตั้งการแจ้งเตือนยอดใช้บริการ Cloudflare และพื้นที่ Google Drive จาก Dashboard ผู้ให้บริการ
- เมื่อเปลี่ยนโดเมน ตรวจ OAuth Callback, `PUBLIC_BASE_URL` และ Cookie/HTTPS ใหม่
- เมื่อ Google Drive OAuth Token ถูกเพิกถอน ให้ Admin เชื่อมต่อกับ **บัญชี Storage เดิม** หากมีไฟล์ที่จัดเก็บไปแล้ว
- ก่อนใช้เอกสารประกอบภาษีหรือสัญญาจริง ให้ผู้ทำบัญชีและผู้มีอำนาจลงนามตรวจแบบฟอร์มและข้อความก่อน
